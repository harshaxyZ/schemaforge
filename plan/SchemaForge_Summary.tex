\section*{What it is}
SchemaForge is a TrueForge agent that turns a natural-language database change into an
evidence-backed migration decision. It inspects a live PostgreSQL~16 target, maps the dependency
blast radius, runs the generated SQL inside a rollback-only shadow sandbox, checks explicit
assertions and rollback equivalence, and then freezes at a human approval checkpoint. It is not a
free-running SQL generator: nothing reaches production without a signed approval bound to the exact SQL and
assertion set, followed by a second Allow/Deny gate in TrueForge.

\section*{Architecture}
Two role-separated Streamable HTTP MCP servers, written in TypeScript, are attached to one TrueForge agent.

\begin{tabularx}{\linewidth}{@{}p{3.9cm}X@{}}
\toprule
\textbf{Component} & \textbf{Responsibility and credentials} \\
\midrule
\texttt{schemaforge-core} :3100 & Schema inspection, bounded read-only queries, dependency analysis, shadow
rehearsal, post-apply verification. Holds only the \texttt{sf\_reader} (production, read-only) and
\texttt{sf\_shadow} credentials. \\
\texttt{schemaforge-executor} :3101 & Exposes a single tool, \texttt{execute\_migration}, marked
\texttt{destructiveHint: true}. Holds the \texttt{sf\_executor} write role (not a superuser) and the
approval-verification secret; has no shadow access. \\
Approval CLI & \texttt{npm run approve} runs in the human's terminal and mints a short-lived
HMAC-SHA256 token. The signing key never enters the agent loop. \\
PostgreSQL :5433 / :5434 & Production and shadow databases in Docker Compose, both seeded with the
same deterministic data (500 users, 14 NULL emails, a duplicate-email group, FK and precision edge cases). \\
\bottomrule
\end{tabularx}

The credential split is structural, not a prompt promise: configuration validation fails fast if the
core process is given the write URL or approval secret.

\section*{End-to-end flow}
\begin{enumerate}
  \item The human states an objective; the agent inspects schema, data and dependencies (read-only).
  \item The agent proposes forward SQL, rollback SQL and typed assertions; the SQL policy classifies them.
  \item \texttt{rehearse\_migration} runs everything on one shadow session and returns a verdict and fingerprints.
  \item The agent publishes a frozen decision packet and stops.
  \item A human mints a token bound to exact SQL, assertions, fingerprints and rehearsal ID (five-minute TTL).
  \item TrueForge pauses the destructive call on an Allow/Deny card; the executor re-verifies, runs the approved assertions and applies atomically.
\end{enumerate}

\section*{Safety properties}
\begin{itemize}
  \item \textbf{Fail-closed SQL policy.} Tier-3 operations, DML, procedural escape hatches, internal-ledger
  access, ambiguous escapes, unknown statements and mixed or non-transactional plans are rejected in code.
  \item \textbf{Deterministic sandbox.} Forward SQL, assertions, lock observation, fingerprints and rollback run on one
  shadow connection; an outer \texttt{ROLLBACK} always runs, even on success.
  \item \textbf{Assertions, not vibes.} Each check declares an expected outcome (\texttt{first\_value\_true},
  \texttt{scalar\_equals}, \texttt{returns\_rows}, \texttt{returns\_no\_rows}); returning without error never passes.
  \item \textbf{Rollback equivalence.} Rollback SQL runs under a savepoint and must restore the exact baseline fingerprint.
  \item \textbf{Exact-action approval.} The HMAC covers SQL and assertion-set hashes, baseline and expected fingerprints,
  rehearsal ID, action, target, nonce, issue time, expiry and single-use intent.
  \item \textbf{Replay, drift and postcondition checks.} The nonce is claimed atomically in a production ledger; the
  apply aborts on baseline drift, then rolls back unless both the post-fingerprint and all approved assertions pass.
  Applies are serialized with an advisory lock under statement and lock timeouts.
\end{itemize}

\section*{How the verdict is decided}
Computed by code in \texttt{rehearse\_migration}; the model explains the verdict but cannot change it.

\begin{tabularx}{\linewidth}{@{}Xl@{}}
\toprule
\textbf{Evidence} & \textbf{Verdict} \\
\midrule
Policy rejects the SQL (prohibited, unsupported, non-transactional) & rejected before rehearsal \\
Forward SQL fails, or any assertion fails                           & \texttt{DO\_NOT\_APPLY} \\
Rollback supplied but does not restore the baseline fingerprint     & \texttt{DO\_NOT\_APPLY} \\
No rollback supplied, or the plan is classified destructive         & \texttt{REVIEW} \\
Rehearsal, assertions and rollback all verified                     & \texttt{APPLY} \\
\bottomrule
\end{tabularx}

\section*{Where production apply is refused}
\begin{tabularx}{\linewidth}{@{}lX@{}}
\toprule
\textbf{Code} & \textbf{Cause} \\
\midrule
\texttt{TOKEN\_MALFORMED} / \texttt{SIGNATURE\_INVALID} & Token unparseable or signed with the wrong key \\
\texttt{HASH\_MISMATCH} / \texttt{ASSERTIONS\_MISMATCH} / \texttt{TARGET\_MISMATCH} & SQL or assertions edited after approval, or wrong target \\
\texttt{TOKEN\_EXPIRED} / \texttt{TOKEN\_NOT\_YET\_VALID} / \texttt{TTL\_EXCEEDED} & Outside the validity window or TTL too long \\
\texttt{REPLAY\_DETECTED}      & Nonce already claimed in the ledger \\
\texttt{SCHEMA\_DRIFT}         & Production no longer matches the rehearsed baseline \\
\texttt{POSTCONDITION\_FAILED} & Post-apply fingerprint differs; transaction rolled back \\
\texttt{SQL\_POLICY\_REJECTED} & Statement fails the policy re-check in the executor \\
\bottomrule
\end{tabularx}

\section*{Demo scenarios}
\textbf{A --- knowing when to stop.} ``Make \texttt{users.email} \texttt{NOT NULL} and \texttt{UNIQUE}.''
The agent observes 14 NULLs and a duplicate group; the naive migration fails rehearsal, the verdict is
\texttt{DO\_NOT\_APPLY}, and no production tool is called.

\textbf{B --- safe action behind two gates.} ``Add an optional \texttt{phone VARCHAR(32)} column.''
Rehearsal passes, rollback (\texttt{DROP COLUMN phone}) restores the baseline, and an
\texttt{information\_schema} assertion confirms the column. The human mints a token, TrueForge shows
Allow/Deny, the executor applies atomically, and reusing the token returns \texttt{REPLAY\_DETECTED}.

\section*{Stack and validation}
TrueForge 0.2.1 harness, Node.js 22.14+, TypeScript MCP servers, PostgreSQL~16 in Docker Compose,
Daytona sandbox for helper code. Validate with \texttt{npm run check}, \texttt{npm run build}, \texttt{npm test} and
\texttt{docker compose config --quiet}. No mocked responses: databases, roles, rehearsal and migration are real.
